# AI Agent Tool-Permission & Policy Guardrails: worked example

> Run on synthetic data with `llm-agent` engine, seed 63647, knobs {}, in 0.7 s on Python 3.13.13. Every number below is read from `starter/results.json`, which `make test` regenerates and checks. Synthetic results are easier than production: they show the mechanics and the traps, not what you will measure on your data.

## 1. Frame the case

**Objective.** Authorise every agent tool call against user intent, data sensitivity and least privilege in real time, blocking unsafe or out-of-scope actions.

**Constraints that shape the design.** Under 20 ms per tool call; Deterministic policy where required; Audit of every decision

**Label in this use case.** For "AI Agent Tool-Permission & Policy Guardrails": Authorise every agent tool call against user intent, data sensitivity and least privilege in real time, blocking unsafe or out-of-scope actions. Define the label exactly as in milestone M1: what counts as a positive or a correct outcome, and when it becomes known. Design around this trap first: Red-team traces generated by builders.

## 2. Choose the signals

Your strongest signal is **Intent-action consistency** (does action match user request). Its rule: Intent model. In the starter, the closest executable idea is **typed read-only tools**: narrow queries for context and evidence, with no free-form shell or query language. Map your columns in `starter/` before you change anything else; the full list of signals and engine features is in `starter/usecase.json`.

## 3. Meet the first trap

Records can carry planted instructions. The naive agent followed them in 61.5% of injected cases and took 7 unsafe actions; it also decided cases whose deciding evidence was unavailable.

## 4. Baseline against the stronger design

The guarded agent treats tool output as data, verifies every claim against a cited line and escalates when evidence is missing: injection success 0.0%, unsafe actions 0, accuracy on the cases it decides 100.0%, escalating 13.0%.

| Result | Value |
|---|---|
| Injection success, naive | 61.5% |
| Injection success, guarded | 0.0% |
| Unsafe actions, naive versus guarded | 7 vs 0 |
| Accuracy on auto-decided cases, guarded | 100.0% |
| Escalation rate, guarded | 13.0% |

## 5. An edge case from the blueprint

**Legitimate multi-step task looks like out-of-scope action.** agent blocked unnecessarily. Planned response: Task-plan declaration and scoped delegation. Write the test that replays this case through your pipeline before you tune anything.

## 6. What to expect on your own data

The planner is scripted so the harness is deterministic. Keep the planted-injection tests, the step budget and the verifier when you put a model behind the same typed tools.

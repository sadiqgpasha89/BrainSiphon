- **Baseline model:** Product owners writing notes by hand from a list of merges, because it is the usual approach.
- **Production model:** A drafting pipeline that groups changes by type and audience, writes plain notes with links, runs filters for internal text and routes the draft to the product owner.
- **Intended use:** Draft release notes from merged pull requests, issues and labels, grouped for customers and for operators, with links to the sources, for the product owner to approve.
- **Out of scope:** - Author name: personal data.<br>- Branch name: an artefact.<br>- Commit hash: an identifier.
- **Primary metrics:** - Link correctness<br>- Breaking change recall<br>- Editor change rate
- **Measured values (fill in):** ____________
- **Slices reported:** - Repository, language and team<br>- Change size and risk tier<br>- Contributor tenure and service criticality<br>- Report the metric and its interval on each slice; flag any slice whose gap to the overall result exceeds the agreed tolerance
- **Calibration:** Calibrate the confidence that triggers abstention: among answers the system was 90% sure about, about 90% should be judged grounded and correct by humans.
- **Known failure modes:** - Missing labels<br>- Embargoed fix<br>- Large release
- **Human oversight:** human-on-the-loop: The system acts within a bounded action space and a person monitors, samples and can halt it. The uncertain band routes to a review queue with a time limit.

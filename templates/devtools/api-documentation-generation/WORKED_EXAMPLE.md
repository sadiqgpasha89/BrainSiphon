# API Documentation Generation: worked example

> Run on synthetic data with `llm-rag` engine, seed 12975, knobs {}, in 1.9 s on Python 3.13.18. Every number below is read from `starter/results.json`, which `make test` regenerates and checks. Synthetic results are easier than production: they show the mechanics and the traps, not what you will measure on your data.

## 1. Frame the case

**Objective.** Generate and update API reference docs and examples from code, schemas and tests so documentation stays accurate, with examples executed in CI.

**Constraints that shape the design.** Every example runs in CI; Documentation matches the OpenAPI or schema; Owners review changes

**Label in this use case.** For "API Documentation Generation": Generate and update API reference docs and examples from code, schemas and tests so documentation stays accurate, with examples executed in CI. Define the label exactly as in milestone M1: what counts as a positive or a correct outcome, and when it becomes known. Design around this trap first: Prose with no tests.

## 2. Choose the signals

Your strongest signal is **Schema and type information** (endpoints, fields and types). Its rule: From code. In the starter, the closest executable idea is **source type**: reference, tutorial or changelog, so factual answers come only from reference pages. Map your columns in `starter/` before you change anything else; the full list of signals and engine features is in `starter/usecase.json`.

## 3. Meet the first trap

Questions with no answer in the corpus are answered anyway by a naive pipeline: it hallucinated on 100.0% of them. Stale or superseded passages caused 7 errors.

## 4. Baseline against the stronger design

The guarded pipeline checks that every claim cites a supporting passage and abstains otherwise: hallucination 0.0%, answered precision 100.0%, at the cost of declining 43.8% of answerable questions.

| Result | Value |
|---|---|
| Hallucination rate, naive | 100.0% |
| Hallucination rate, guarded | 0.0% |
| Answered precision, naive | 52.1% |
| Answered precision, guarded | 100.0% |
| Answerable questions it declined, guarded | 43.8% |

## 5. An edge case from the blueprint

**Breaking change.** the docs and code disagree. Planned response: CI blocks stale docs. Write the test that replays this case through your pipeline before you tune anything.

## 6. What to expect on your own data

The language model here is a deterministic stand-in so the harness is exact; the harness, the golden set and the abstention metric carry over to a real model. Re-measure everything with your model.

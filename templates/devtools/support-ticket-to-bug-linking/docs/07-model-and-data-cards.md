- **Baseline model:** Support agents searching the bug tracker by keywords, because it is the usual process.
- **Production model:** A linking model with redaction, a suggestion UI for agents and an impact dashboard for product teams that shows counts by bug and tier.
- **Intended use:** Link customer support tickets to the engineering bugs behind them so engineering sees real customer impact and support sees fix status.
- **Out of scope:** - Customer name: personal data.<br>- Agent name: irrelevant.<br>- Ticket channel: weak link.
- **Primary metrics:** - Precision at three<br>- Redaction recall<br>- Impact count accuracy

- **Slices reported:** - Repository, language and team<br>- Change size and risk tier<br>- Contributor tenure and service criticality<br>- Report the metric and its interval on each slice; flag any slice whose gap to the overall result exceeds the agreed tolerance
- **Calibration:** Calibrate scores so that a score of 0.02 means a 2% event rate on the current population, per segment, because thresholds and costs are applied to the probability, not the rank.
- **Known failure modes:** - No matching bug<br>- Many tickets one bug<br>- Misleading link
- **Human oversight:** autonomous-with-audit: The system acts on its own inside guardrails; every decision is logged for replay, and humans review aggregate behaviour, drift and appeals rather than each decision.
